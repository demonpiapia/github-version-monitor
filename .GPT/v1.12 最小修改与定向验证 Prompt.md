# 5. P2 — Step 3 housekeeping 不得阻断核心业务

当前 Step 3 的职责主要是：

```text
heartbeat
+
backup 清理
+
trash housekeeping
```

其中 backup/trash 清理属于 housekeeping，不属于核心版本监测业务。

目标：

> housekeeping 的普通清理失败，不应阻断核心业务流程。

尤其不能出现：

```text
trash/backup 清理失败
        ↓
GitHub version monitor 整轮失败
```

需要区分：

### 核心失败

例如：

```text
无法取得必要运行状态
核心 API 处理失败
result.json 无法安全写入
主 md 无法安全提交
```

这些可以导致整轮 failed。

### housekeeping failure

例如：

```text
创建 trash 失败
旧 backup 无法移动
清理某个旧 backup 失败
```

这些原则上：

```text
记录 warning / diagnostic
继续核心流程
```

不要让 housekeeping 失败破坏已经可用的核心业务流程。

**注意：运行锁 heartbeat 不是普通 housekeeping。**

如果 heartbeat 失败导致无法确认当前执行仍然拥有锁，则必须继续保持安全优先级，不能为了“继续运行”而放宽并发保护。

也就是说：

```text
lock ownership / heartbeat
    ≠
backup cleanup
```

不要混为一谈。
