## 11. 项目协作要求：推送说明规范（强制）

**本项目约定**：本地所做的任何修改，在推送时必须附加到推送说明中，以便云端 GPT agent 了解并同步我们所做的变更。

### 11.1 强制规则

```text
1. 每次 git push 前，commit message 必须说明本次变更内容
2. 禁止使用无信息量的 commit message（如 "update"、"fix"、"misc"）
3. 禁止把多个不相关变更混在一个 commit 里而不加说明
4. 推送说明必须让未参与本地对话的 agent 能独立理解本次变更
```

### 11.2 Commit message 格式

```text
<type>: <一句话概括变更>

<正文：列出具体变更项>
- 变更了什么文件
- 为什么变更（用户要求 / 验证发现 / 修复）
- 影响范围（是否影响生产行为、是否需重新验证）
```

`type` 取值：`feat`（新增能力）/ `fix`（修复）/ `chore`（工程性调整）/ `docs`（文档）/ `test`（测试资产）。

### 11.3 示例（本项目历史真实 commit）

```text
feat: add SKILL-v1.8

chore: track .output/ directory, remove from .gitignore

feat: add SKILL-v1.7 production validation report + test evidence
- production-validation-report-v17-final.md: full validation report (46 tests, 44 PASS, 2 FAIL)
- .production-validation-v17-final/: clean-room test evidence (214 files, T00-T46)
- v16-v17.diff: git diff between SKILL-v1.6.md and SKILL-v1.7.md
- .gitignore: remove .monitor/, add .GPT/
- P1 bug found: $commitSucceeded never set to $true in Step 5 (regression from v1.6)
```

### 11.4 本轮验证的推送要求

你完成 v1.8 验证后推送时，commit message 必须包含：

```text
1. 最终 Verdict（PRODUCTION_READY / NOT_READY / BLOCKED）

4. 本轮新增或发现的关键问题（若有）

```

### 11.5 禁止事项

```text
- 禁止静默推送（无 commit message 正文）
```
