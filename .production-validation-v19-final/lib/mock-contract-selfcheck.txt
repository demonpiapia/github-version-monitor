# Mock Contract Self-Check [D3]

对齐目标：SKILL-v1.9.md L341-L366（Step 2 的 Invoke-RestMethod 消费契约）。

## 契约提取（SKILL L341-L366）

成功路径：
- L341 `if ($j.tag_name -and $j.published_at)` → `ok`
- L346 `elseif ($j.tag_name)` → `metadata_incomplete`
- L349 `else` → `invalid_response`

异常路径：
- L354 `$_.Exception.Response.StatusCode` → `[int]$code`
- L356-357 `$_.Exception.Response.Headers` → `Get-ResponseHeaderValue $Headers 'X-RateLimit-Remaining'`
- L359-366 状态机分类：401 / 404 / 429 / 403(RL=0) / 403(RL>0) / ≥500 / 其他 / 无 Response

## Headers 类型选择记录

**选择：`System.Net.WebHeaderCollection`（外层）+ `HttpResponseMessage.Headers`（内层透传）**

理由：
1. SKILL L322-328 `Get-ResponseHeaderValue` 支持三种访问分支：
   - `WebHeaderCollection.Get($Name)` — 直接命中
   - `$Headers[$Name]` — 索引器
   - `$Headers.TryGetValues($Name, [ref]$values)` — `HttpResponseHeaders` 分支
2. 真实 `Invoke-RestMethod` 抛出的 `WebException.Response` 是 `HttpResponseMessage`，其 `.Headers` 为 `HttpResponseHeaders`。
3. `HttpResponseHeaders` 支持 `TryGetValues`（L326 分支命中）；`WebHeaderCollection` 不支持 `TryGetValues`，但支持 `.Get()`（L324 分支命中）。
4. 为贴近真实响应形状，异常对象的 `.Response` 使用 `HttpResponseMessage`，其 `.Headers` 为 `HttpResponseHeaders`；构造时用 `TryAddWithoutValidation` 写入 `X-RateLimit-Remaining`。
5. 兼容 PS5.1：`System.Net.Http.HttpResponseMessage` 在 PS5.1 中需 `Add-Type -AssemblyName System.Net.Http`；`System.Net.WebHeaderCollection` 是 .NET Framework 原生类型，PS5.1 和 PS7 均可用。

## 关键结论

- Headers 类型选择：`System.Net.WebHeaderCollection` 作为构造输入，`HttpResponseMessage.Headers`（`HttpResponseHeaders`）作为异常对象的 `.Response.Headers`。SKILL L326 `TryGetValues` 分支可命中。
- 所有 12 个场景的 mock 返回值/异常对象形状与 SKILL L341-L366 的提取表达式一一对齐，无遗漏。
- `network_error` 场景使用 `System.Exception`（无 `.Response`），确保 L354/L356 均跳过，最终 L366 命中。
